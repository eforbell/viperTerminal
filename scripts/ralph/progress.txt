# Feature 2: Historical Charts & News Feed - Progress Log

## Codebase Patterns

### From Feature 1 (Reference AGENTS.md for full details)
- **Virtual Environment**: Always use `.venv/bin/python` for commands
- **Async Testing**: Use `@pytest.mark.asyncio` with `asyncio_mode = "auto"`
- **Textual Testing**: Use `async with app.run_test() as pilot` pattern
- **External APIs**: Always mock yfinance and httpx in tests
- **Type Checking**: `mypy --strict` requires explicit annotations everywhere
- **Coverage**: Maintain 90%+ test coverage
- **Event Handlers**: Use `on_{widget_name}_{event_name}` pattern (snake_case)
- **Custom Events**: Define as nested classes inheriting from `Message`
- **Panel Toggle Pattern**: Use `styles.display = "block"/"none"` for visibility
- **Focus Management**: Set `can_focus = True` and use `priority=True` on bindings
- **Responsive Layout**: Use `on_resize()` handler (no @media queries in TCSS)

### New Patterns (Add as discovered)
- **Period Mapping**: User-friendly periods (1W, 1M) map to yfinance periods (5d, 1mo) via dicts
- **Interval Selection**: Match data interval to period length for appropriate granularity
- **Volume Integer Conversion**: Convert pandas volume to int: `[int(v) for v in hist["Volume"].tolist()]`
- **Mock DataFrames**: Use `pd.DataFrame` with `pd.date_range` index for realistic test mocks

## 2026-01-07 - VPR-017
- Implemented chart rendering engine with Braille and block character support
- Created chart_renderer.py with ChartRenderer, ChartDimensions, RenderedChart classes
- Braille rendering: 2x4 dots per character (Unicode U+2800-U+28FF) for high resolution
- Block rendering: fallback using ▁▂▃▄▅▆▇█ characters (8 vertical levels)
- Auto-scaling: normalize data to 0-1 range, scale to chart height
- Auto-downsampling: evenly-spaced sampling when data exceeds chart width
- Y-axis: 3-5 price labels distributed vertically, right-aligned with │ separator
- X-axis: two-line design (border + date labels showing first/last dates)

### Files Changed
- `viper/widgets/chart_renderer.py` (new, 434 lines, 96% test coverage)
- `tests/test_chart_renderer.py` (new, 393 lines, 29 tests)
- `AGENTS.md` (updated with VPR-017 learnings)
- `scripts/ralph/features/feature-2-prd.json` (marked VPR-017 as passing)

### Learnings
- **Type Overloading**: Used `@overload` decorator for _downsample method to preserve type safety (list[float] vs list[datetime])
- **Downsampling Gotcha**: Must use original data for min/max to avoid losing extremes during downsampling
- **Type Narrowing**: Required `cast()` and `isinstance()` checks to help mypy understand type narrowing in generic functions
- **Multi-Line Returns**: When functions return strings with `\n`, use `.split("\n")` and `.extend()` not `.append()`
- **Braille Unicode**: Range U+2800-U+28FF provides 256 patterns (2 columns × 4 rows of dots per character)
- **Braille Dot Mapping**: Left column uses dots 1-3,7; right column uses dots 4-6,8
- **Chart Dimensions**: Subtract axis widths from total dimensions before rendering chart area
- **Normalization Formula**: `(value - min) / (max - min)` maps to 0-1, then scale to target resolution
- **Even-Spaced Downsampling**: `step = len(data) / target; sampled = [data[int(i * step)] for i in range(target)]`
- **Floating Point Tests**: Use epsilon tolerance (0.011) instead of exact equality for float comparisons
- **Edge Case Testing**: 29 tests covering empty data, single point, flat lines, zigzag, negative prices, large ranges
- **Dataclass Pattern**: RenderedChart dataclass cleanly returns multiple related values (lines, dimensions, min/max)
- **Type Assertions**: Add `assert isinstance()` checks when downcasting union types to help mypy

### Implementation Notes
- Skipped color support (green/red for trends) - marked as enhancement for later
- Focus was on core rendering quality and comprehensive testing
- Both rendering styles (Braille and Block) fully functional and tested
- Ready for integration into ChartPanel widget (VPR-018)

### Learnings
- **Timeframe Mapping Pattern**: Store key-to-period dict in widget for centralized management and easy lookup
- **Multiple Action Methods**: Create individual `action_timeframe_N()` methods that delegate to shared `_change_chart_timeframe(key)` helper
- **Conditional Actions**: Check panel visibility flag (`_chart_panel_visible`) before processing timeframe changes
- **Widget Query Methods**: Add public `get_timeframe_for_key(key)` method for app to access widget's mappings
- **Async Change Method**: `async change_timeframe(period)` checks if ticker exists and period differs before reloading
- **Rich Markup Escaping**: Use `\\[` to escape literal brackets in markup (e.g., `\\[1]` for key indicator in UI)
- **Markup Tag Nesting**: Must properly nest tags: `[b][cyan]...[/cyan][/b]` not `[b][cyan]...[/b][/cyan]` to avoid MarkupError
- **Active/Inactive Styling**: Use `[b][cyan]` for active period, `[dim]` for inactive in timeframe bar
- **Height Adjustment**: Update available height calculation when adding UI elements: `- 7` instead of `- 6` for new timeframe bar
- **No Redundant Fetches**: Check `period != self._current_period` to avoid re-fetching when same period selected
- **Natural Persistence**: Timeframe persists via `_current_period` state - no special persistence logic needed
- **Test Comprehensiveness**: 8 tests cover: key mappings, invalid keys, conditional behavior, same period, no ticker, UI display, persistence
- **AsyncMock for Services**: Use `AsyncMock` when mocking async functions like `fetch_historical_data` in tests
- **All Tests Pass**: 22/22 chart_panel tests pass, mypy --strict passes, ready for production
