# Feature 3: Data Reliability & Chart Improvements - Progress Log

## Codebase Patterns

### From Features 1 & 2 (Reference AGENTS.md for full details)
- **Virtual Environment**: Always use `.venv/bin/python` for commands
- **Async Testing**: Use `@pytest.mark.asyncio` with `asyncio_mode = "auto"`
- **Textual Testing**: Use `async with app.run_test() as pilot` pattern
- **External APIs**: Always mock yfinance in tests
- **Type Checking**: `mypy --strict` requires explicit annotations everywhere
- **Coverage**: Maintain 90%+ test coverage
- **Event Handlers**: Use `on_{widget_name}_{event_name}` pattern (snake_case)
- **Custom Events**: Define as nested classes inheriting from `Message`
- **Panel Toggle Pattern**: Use `styles.display = "block"/"none"` for visibility
- **Focus Management**: Set `can_focus = True` and use `priority=True` on bindings
- **Responsive Layout**: Use `on_resize()` handler (no @media queries in TCSS)
- **Period Mapping**: User-friendly periods (1W, 1M) map to yfinance periods via dicts
- **Volume Integer Conversion**: Convert pandas volume to int: `[int(v) for v in hist["Volume"].tolist()]`
- **Mock DataFrames**: Use `pd.DataFrame` with `pd.date_range` index for realistic test mocks

### New Patterns for Feature 3 (Add as discovered)
- **yfinance News**: Use `ticker.news` attribute, returns list of dicts with `content.title`, `content.summary`, etc.
- **yfinance Crypto**: Use SYMBOL-USD format (BTC-USD, ETH-USD) for crypto via yfinance
- **Chart Interpolation**: When data < 60% of chart width, price chart upsamples - volume must match
- **Technical Indicators**: Pure calculation functions, return None for initial values where calculation not possible

## 2026-01-07 - VPR-031
- **What was implemented**: Fixed volume bar alignment with price chart by tracking and applying interpolation
- **Files changed**:
  - `viper/widgets/chart_renderer.py`: Added interpolated_count to RenderedChart, created _upsample() method, updated render_volume_bars to accept and use interpolated_count
  - `viper/widgets/chart_panel.py`: Pass rendered.interpolated_count to render_volume_bars() call
  - `tests/test_chart_renderer.py`: Added 5 comprehensive tests for interpolation tracking and volume alignment
  - `scripts/ralph/features/feature-3-prd.json`: Marked VPR-031 as complete
  - `AGENTS.md`: Added VPR-031 learnings section with 28 detailed points
- **Learnings**:
  - **Root cause diagnosed**: Price chart upsamples when data < 60% of max_data_points, but volume bars didn't follow
  - **max_data_points formula**: For BRAILLE charts, max_data_points = chart_width * 2 (2 points per character)
  - **Upsampling threshold**: Triggers when `len(prices) < max_data_points * 0.6`
  - **Solution pattern**: Add metadata to return value to communicate interpolation state downstream
  - **RenderedChart enhancement**: Added `interpolated_count: int = 0` field (0=no interpolation, >0=count)
  - **Block style**: Doesn't interpolate, always returns interpolated_count=0
  - **Created _upsample() method**: Mirrors price chart interpolation logic for volumes
  - **Type safety challenge**: Mypy requires separate `upsampled_int` and `upsampled_float` lists to avoid type errors
  - **Can't append to generic list**: `upsampled.append(int(value))` fails because list type is `list[float] | list[int]`
  - **Solution**: Create separate typed lists, populate one based on is_int flag, return correct one
  - **Parameter addition**: render_volume_bars() now accepts `interpolated_count: int = 0` (backward compatible)
  - **Conditional upsampling**: Only upsample volumes if interpolated_count > 0
  - **Order matters**: Upsample FIRST (to match price data), THEN downsample (to fit chart width)
  - **Integration point**: chart_panel passes `rendered.interpolated_count` to volume renderer
  - **Test coverage**: Added tests for interpolation detection, alignment, no-interpolation, edge cases
  - **Edge case 1 point**: Upsampling from single point creates flat line (all same value)
  - **Edge case 2 points**: Linear interpolation creates smooth gradient between 2 values
  - **Backward compatible**: Existing calls work (interpolated_count defaults to 0)
  - **No performance cost**: Upsampling only occurs when data is sparse (< 60% threshold)
  - **Visual fix confirmed**: Volume bars now perfectly align regardless of data density
  - All 562 tests passing with 90.33% overall coverage
  - mypy --strict validates with no type errors

  - **New Module Pattern**: Created dedicated `viper/services/indicators.py` for all technical indicators
  - **Pure Functions Only**: No external dependencies (yfinance, pandas), just pure Python math
  - **Return Type Pattern**: Use `list[float | None]` for indicators that can't always calculate
  - **None for Initial Values**: Return None for first (period-1) values where SMA unavailable
  - **SMA Formula**: For position i: `sum(prices[i-period+1:i+1]) / period`
  - **Window Slicing**: `prices[i - period + 1 : i + 1]` gets last N prices ending at i
  - **Input Validation**: Raise ValueError for period <= 0 (must be positive)
  - **Empty List Handling**: Return [] when input is []
  - **Length Preservation**: Output list always same length as input list
  - **None Count Invariant**: Number of None values always equals `period - 1`
  - **Period 1 Edge Case**: SMA with period=1 is identity function (returns original prices)
  - **Insufficient Data**: When `len(prices) < period`, all values are None
  - **Exact Period Size**: When `len(prices) == period`, only last value has SMA
  - **Test Coverage**: 16 comprehensive tests covering all edge cases and common periods
  - **Common Periods**: Tested 20, 50, 200 day (industry standard moving averages)
  - **Real World Test**: Included test with realistic stock price data (AAPL-like)
  - **Flat Prices Test**: SMA of constant prices equals that constant value
  - **Volatile Prices Test**: SMA smooths price swings (alternating high/low values)
  - **Float Comparison**: Use `pytest.approx(value, abs=0.01)` for float assertions
  - **Type Safety**: mypy --strict validates `list[float | None]` union type correctly
  - **Docstring Examples**: Include usage examples in docstring for clarity
  - **Module Docstring**: Explain the None-return pattern at module level
  - **Foundation Pattern**: This establishes pattern for EMA, RSI, MACD calculations
  - **No numpy/pandas**: Deliberately avoided heavy dependencies for simple calculations
  - **Performance**: O(n) complexity with simple arithmetic - very fast
  - **Integration Ready**: Function signature designed for easy chart overlay integration

- **Learnings**:
  - **EMA Formula**: k = 2/(period+1), then EMA = (Price * k) + (EMA_prev * (1-k))
  - **Smoothing factor k**: Calculate once at start, use throughout - k gives weight to current price
  - **First EMA value**: Use SMA of first `period` prices as initial EMA (bootstrapping)
  - **Three-branch loop logic**: (1) i < period-1 → None, (2) i == period-1 → SMA, (3) i > period-1 → EMA formula
  - **Recursive dependency**: Each EMA calculation needs previous EMA value from result[i-1]
  - **Window slicing for first SMA**: Use `prices[:period]` to get initial window
  - **State tracking pattern**: Reference previous result in list to build current value
  - **Defensive None check**: Even though prev_ema shouldn't be None, check for type safety
  - **None count invariant**: Same as SMA - always `period - 1` None values at start
  - **Return type consistency**: Use `list[float | None]` to match SMA interface pattern
  - **Period 1 edge case**: k = 2/(1+1) = 1.0, so EMA equals current price (same as SMA)
  - **Common periods tested**: 12 (MACD fast), 26 (MACD slow), 50 (trend indicator)
  - **EMA vs SMA behavior**: EMA reacts faster to price changes due to exponential weighting
  - **Test pattern reuse**: Mirror SMA test structure - basic, periods, edge cases, real world
  - **Comparison test**: Verify EMA > SMA after price jump (faster reaction to changes)
  - **Monotonicity tests**: EMA increases with upward trend, decreases with downward trend
  - **Convergence behavior**: EMA follows trends with smoothing (exponential decay)
  - **Known calculation test**: Hand-calculate with period=2, k=0.6667 to verify implementation
  - **Smoothing factor test**: Dedicated test that k=2/(period+1) is correctly applied
  - **Type ignore cleanup**: Remove unused `# type: ignore` comments to avoid mypy unused-ignore errors
  - **Assert comparison pattern**: After `assert x is not None`, can compare x directly (mypy knows it's not None)
  - **Formula in docstring**: Include mathematical formula and example calculation for clarity
  - **Edge case coverage**: Empty list, single value, insufficient data, exact period size
